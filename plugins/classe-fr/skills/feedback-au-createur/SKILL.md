# Feedback au créateur

Lire `references/confidentialite.md` avant de poser toute question.

1. Choisir un type : `bug`, `idée`, `ressource`, `besoin pédagogique`, `cua-accessibilite` ou `confidentialité`.
2. Décrire un contexte pédagogique non identifiable : niveau, discipline, action tentée, résultat et impact.
3. Pour un bug, ajouter les étapes de reproduction et le résultat attendu. Pour une idée, préciser le bénéfice enseignant ou élève recherché. Pour une ressource, fournir uniquement un lien public et sa licence.
4. Faire confirmer explicitement qu'aucun nom, document d'élève, message familial, capture d'écran ou donnée sensible n'est inclus. Pour un brouillon rédigé dans un fichier texte, proposer le pré-contrôle local décrit dans `references/confidentialite.md`, puis demander la relecture humaine explicite.
5. Générer un brouillon à partir de `assets/modeles/feedback.md`, à enregistrer dans `feedbacks/` de l'espace professeur.
6. Indiquer à l'enseignant de copier le brouillon dans le formulaire GitHub public. Préciser qu'une issue, un commentaire ou une pièce jointe peut être visible publiquement. Ne jamais créer ou envoyer l'issue sans confirmation séparée.
7. Pour le créateur, appliquer `references/triage-feedbacks-enseignants.md` : qualifier le retour, annoncer un état sans détail sensible, lier l'issue de réalisation et inscrire toute décision livrée dans le journal de version.

Ne jamais inclure de donnée d'élève, capture d'ENT, message aux familles ou pièce jointe identifiable. Pour un sujet de confidentialité, ne demander aucune pièce jointe et limiter la description au strict nécessaire. Le créateur assure le triage par labels et journal de version.
